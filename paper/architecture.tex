\chapter{System Architecture}
\label{sec:architecture}

The proposed system is organized as a five-stage pipeline: an ingestion and indexing layer, an agentic planner, an evidence sufficiency gate, a grounded generator with a faithfulness gate, and an attribution layer. Unlike passive single-pass retrieval pipelines, the planner and sufficiency gate form a closed feedback loop, allowing the system to iteratively gather additional evidence before committing to an answer; the generator and faithfulness gate form a second loop that removes unsupported claims from the draft answer. Chapter~\ref{sec:graph} refines each stage into individual graph nodes.

\section{Overview}
Figure~\ref{fig:architecture} illustrates the overall data flow. A user query enters the Agentic Planner, which issues retrieval actions against a dual index built during ingestion. After each retrieval round, the Evidence Sufficiency Gate evaluates whether the collected evidence is adequate to answer the query. If not, control returns to the planner for another retrieval iteration; if so, the system generates an answer from the evidence alone. The Faithfulness Gate then checks every claim in that answer against the evidence, returning it for rewriting if needed, before attribution is produced.

\section{Ingestion and Indexing Layer}
Each PDF page in the corpus is rasterized into a page image, which is embedded using a visual document retriever (ColQwen2, of the ColPali family~\cite{faysse2025colpali}) to produce patch-level embeddings without requiring OCR or layout parsing. In parallel, narrative text is extracted and segmented into chunks, which are embedded using a retrieval-trained scientific text encoder (SPECTER2~\cite{singh2023scirepeval}) and stored in a FAISS~\cite{johnson2019faiss} index. This produces two complementary indexes:
\begin{itemize}
    \item \textbf{Visual index:} Page-level patch embeddings for retrieving tables, figures, and dense visual content.
    \item \textbf{Textual index:} Chunk-level embeddings for retrieving narrative claims and discussion.
\end{itemize}

\section{Agentic Planner}
The Agentic Planner is an LVLM-driven controller that operates an iterative reasoning loop (Thought $\rightarrow$ Action $\rightarrow$ Observation), inspired by the ReAct paradigm~\cite{yao2023react}. At each step, the planner selects one of the following tools, which correspond to the action space $\mathcal{A}$ defined in Chapter~\ref{sec:methodology}:
\begin{itemize}
    \item \texttt{TextRetriever(query)}: dense retrieval over the textual index.
    \item \texttt{TableRetriever(query)}: locates a table through the visual index, then parses it with a table-structure recogniser~\cite{smock2022pubtables} into structured form, preserving the page coordinates of every cell.
    \item \texttt{FigureRetriever(query)}: visual retrieval over the ColQwen2 page index (of the ColPali family), returning figures together with their patch-similarity scores.
\end{itemize}
A fourth tool, \texttt{RegionZoom}, re-renders a retrieved figure at higher resolution; it is not chosen by the planner but runs automatically when the figure covers less than 30\% of its page.
Multi-hop navigation (for example, from a textual claim to its supporting table) requires no dedicated tool: it arises from the loop itself, since each retrieved observation informs the query the planner issues next. All tool invocations and their results are recorded in a structured scratchpad, which later serves as the auditable retrieval log referenced in Chapter~\ref{sec:introduction}.

\section{Evidence Sufficiency Gate}
After each retrieval round, the Evidence Sufficiency Gate determines whether the evidence accumulated in the scratchpad is sufficient to answer the query. It is implemented as an LLM-as-judge: the prompted model first names the facts in the evidence that answer the question, citing their evidence identifiers, and only then returns its verdict, so that a verdict cannot precede its justification. (A learned gate, a classifier over retrieval-confidence features, was considered and not built: no training labels for sufficiency exist.) If the gate reports insufficient evidence, control returns to the Agentic Planner for an additional retrieval iteration, bounded by a maximum iteration count to prevent unbounded looping. This mechanism directly implements Objective 3 and mitigates hallucination by preventing the system from answering without grounded proof.

\section{Grounded Generator and Faithfulness Gate}
Once the Sufficiency Gate confirms sufficiency, an open-weight vision-language model run locally (Qwen2.5-VL-7B~\cite{bai2025qwen25vl}, 4-bit) generates an answer strictly conditioned on the retrieved evidence pool; the generator has no other access to the corpus. It writes the answer as a list of claims, each citing its evidence (a quote, a table cell, or a figure observation). The Faithfulness Gate then checks each claim against the evidence it cites, first exactly and then with a support check by the model. Any unsupported claim sends the draft back to the generator for rewriting, again bounded by a maximum iteration count.

\section{Attribution Layer}
Visual attribution prefers exact positions preserved during retrieval and ingestion: the cell coordinates recorded by \texttt{TableRetriever}, the bars of vector charts read from the PDF, and the positions of quoted sentences, captions and diagram labels on the page. Only for photographs, which have no printed words, are the patch-level similarity scores of ColQwen2 used to localise the most relevant region. Together these yield bounding-box coordinates over the supporting table cell or figure region. This satisfies Objective 4 and provides the fine-grained visual grounding required for human verifiability (RQ3).
